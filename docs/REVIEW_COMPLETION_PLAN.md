## 阶段 3：修改队列与原始数据验证代码

### 3.1 队列

- 新增只读状态命令，报告实际进程线索、计划/完成/失败数和实验源提交；不因报告提交改变而拒绝查看。
- 对已经完成的队列，验证结果完整性后报告完成并退出；不改写原 finished_at，不启动训练。
- 未完成队列仍禁止在不同实验版本或脏代码下继续，避免把不同实现混进同一批结果。
- 发现完成标记与实际文件、配置或指标不符时明确报错，不把缺失单元当完成。
- 补充对应的回归测试与文档命令。

### 3.2 数据与结果审计

- 建立只读审计入口，从原始 CSV 按规定顺序、列选择与 6:2:2 划分独立核对每个单元。
- 验证原始缺失目标掩码；校验训练前缀标准化统计；逐原点核对保存目标对应原 CSV 的 s+1..s+H。
- 验证每次运行的完整配置、seed、方法、骨干配置和代码提交来源；区分数字方法没有使用文本与通用 encoder 配置字段。
- 核对文本记录 ID、反馈来源时间、成熟时刻、无重复更新、warm-up 与 test 状态重置证据。
- 重新计算逐 seed、跨 seed 和配对统计；所有失败或不完整单元单独报出。
- 对审计器注入错误目标、错误掩码、错误 origin 和缺失文件，确认它会拒绝这些伪完成材料。

验收：原有协议检查通过；新审计器对真实 190 单元通过，对构造的错误材料失败；只读命令不修改旧结果。

## 阶段 4：将不被证据支持的结论落实到交付代码和文档
