## 能回答review的部分

本轮建立了一个作者GPT4MTS与iAdapter可在同一目标/评分范围下运行的入口。结果没有支持iAdapter的优越性：静态iAdapter的两项平均误差都更高；GPT4MTS仅在MSE最低，数值适配器在MAE最低。保留所有方法，不仅挑有利指标。

只有一个seed，不计算跨seed SD、置信区间或显著性。静态iAdapter在训练流预热后不再更新，且开发反馈缓存归零并保持零；它不能替代在线iAdapter的结论。原多变量在线结果与此表属于不同任务与协议，不能合并或直接作改进百分比。

## 比较控制与仍存在的设计差异

| 项目 | 本轮处理 |
|---|---|
| 数值输入与目标 | 三方法同一OT历史、H6目标和掩码 |
| 选择/评分 | 相同时间划分；按选择段masked MSE选模型，开发期无更新 |
| 内部骨干 | 两内部方法共享同一新单变量checkpoint，第二层尾部固定插入 |
| GPT4MTS架构 | 六层预训练GPT2，作者历史prompt/patch/RevIN结构；没有插入位置搜索 |
| 文本可用性 | 同一end_date代理限制，真实publication time仍未验证 |
| 实际文本消费 | iAdapter当前文本mean/64；GPT4MTS历史L个时刻CLS/512。历史长度、池化和截断不同，不能称文本输入完全相同 |
| 训练预算 | 骨干/GPT最多30epochs、batch16、Adam1e-3、patience5；内部adapter另有训练流预热 |

因此这张表比较明确配置下的整体系统，不能把差异单独归因于MoE、文本内容质量或在线适配。要隔离文本预算，需要另设控制；不把运行后增加的控制冒充预先完成的实验。

## 实际训练与运行记录

内部骨干和GPT4MTS均在第6个epoch停止，选择第1个epoch。内部骨干共84步优化，由两个内部方法共享，不重复计费；每个内部适配器另外执行206次成熟目标预热更新。GPT4MTS共84个batch优化步骤，没有开发更新。

适配器/模型在静态评分之前可训练的参数分别为10,496、166,832、1,445,384；总预测模型参数（不含独立BERT）分别为37,350、193,686、82,551,560。不能用这些参数数目推断相同训练计算量。

三个单元观测总时长之和约14.2秒；GPT4MTS单元约6.5秒，其中新CLS/512编码约3.0秒。内部方法复用已有BERT mean/64缓存，时间口径并不相同，这些仅用于估计后续执行成本，不是公平效率结论。
