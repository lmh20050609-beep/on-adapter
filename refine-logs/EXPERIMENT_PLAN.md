# iAdapter 重新制定的实验与修订计划

**日期：2026-09-30。状态：执行中。M0/B1/B2完成，B3原质量预检停止，用户要求后继续固定表示探索；详细结果与状态见跟踪表。**

**问题：** 在固定骨干、真实原始目标和逐原点延迟监督下，当前性能受限主要来自文本信息、文本接入，还是在线反馈？

**方法判断：** 保留现有full作为已测参考，下一轮优先隔离瓶颈。能够直接回答review的对照先做；TiMi启发只形成一个有门槛的新表示假设。任何新方法须优于强简单控制，再考虑扩域。没有证据支持恢复普遍SOTA、全部组件必要或语义专家分工。

## 一、为什么现在要改变执行顺序

| 当前可核验结果 | 对下一轮的约束 |
|---|---|
| 原190矩阵H6：full平均MSE最低2/5域、MAE最低1/5；text_add相对数值平均MSE改善0/5域 | 继续加模块或扩seed不能替代文本有效性检验 |
| 新共同OT开发表：iAdapter在线相对数值MSE在Security/Climate只低约0.095%/0.242%，五域MAE均更高 | 主比较必须保留数值强控制，同时补相同OT任务的简单文本控制 |
| GPT4MTS固定在线扩展25/25单元的MSE与MAE比自身静态更高 | 保留作者模型静态结果；不使用退化扩展建立优越性，也不进行开发评分后的学习率翻盘搜索 |
| 删除路由文本梯度在原三域平均MSE更低；去正则/单MLP新增Energy seed出现反转 | 不能依据旧最好结果换默认；需要同起点对照来隔离部署期间反馈贡献 |
| 80同状态文本诊断没有稳定正确内容优势；22/25原full H6运行路由集中 | 先检验可用信号，再考虑路由改变；不把扰动不敏感称作语义鲁棒 |
| 压缩没有候选同时通过两域既定门槛 | 该分支已收束，不追加宽度搜索或放宽门槛 |
| SocialGood有效文本：训练180/540、选择90/90、开发90/90；Energy相应887/887、148/148、148/148 | 检验文本可用性与内容的不同作用；覆盖率变化只是观察，尚不是性能退化的原因证明 |
| 已有原点队列、原CSV核验、51测试、实测成本、完整回复草稿 | 不重做已完成190矩阵；直接复用符合配置、权重和评分范围的控制 |

证据入口：[当前修订结论](review_delivery/REVIEW_DECISIONS.md)、[完整结论核对](review_delivery/CLAIMS_FROM_RESULTS.md)、[静态/在线全部控制](external_baselines/online_evidence/ALL_CONTROLS.md)。原190的60/20/20多变量结果与新60/10/10的OT开发结果分表，不合并胜率。当前Git源提交为cff31c0f65455a0fd29c1e506ec8d045e3b8f55c。

## 三、共同协议与M0前置工作

### 固定开发任务

- 先用Energy、SocialGood，OT单变量，H=6，seeds=2023/2024/2025。选择这两域是为了复用诊断和体现不同文本覆盖，不因为其最好seed；它们已经用于开发，必须继续标注exploratory。
- 原时间排序、前60%训练、60%–70%选择、70%–80%开发评分；80%–100%此前已暴露，不能重新命名为未见测试。
- Energy边界887/1035/1183；SocialGood540/630/720。L=48/36。全部目标与有效掩码对应原CSV，标准化只由训练段决定。
- 使用现有common-OT静态实验的seed-specific数值骨干，d_model=32、2层、batch16预训练配置；不混用原多变量或旧batch32骨干。配置和权重指纹逐项核对后复用，不新增这两域骨干训练。
- 原预测评分；原点t先预测再更新成熟s+6≤t；batch1；末尾不flush；测试/开发开始时优化器、队列和反馈为零；原文本与反馈上下文回放。
- 在线Adam lr=1e-3、weight decay=1e-4、clip=1；full entropy=.02。本轮不搜索在线学习率、温度、专家数、投影宽度或delay。
- end_date仍是可用性代理。所有新文本表示必须只来自该原点已可用记录；不把来源核验误写成真实publication-time无泄漏。

### M0无需训练的检查

1. 核对源文件SHA、保存权重、原点/掩码以及raw预测对应任务；复用已有审计结果，不无目的重复全量检查。
2. 明确frozen_backbone不含adapter，与numeric_static和numeric_online不同。新增此控制可判断warm adapter和online更新相对裸骨干的实际作用。
3. 文本审计：区分原始缺文、清洗后无信息、被字符或token截断；输出训练/选择/开发的覆盖、长度、fact/preds实际token比例和文本年龄。
4. 将选中文本记录ID映射到真正进入BERT的64-token范围。当前记录ID列表不能自动证明每条记录的内容都被编码；新文本生成也只能读相同可见字符串。
5. 检查SocialGood覆盖差异是否由真实来源、合并规则或清洗造成。只审计事实，不先假定需要补齐缺文，也不用未来文本填训练空白。
6. 若发现目标错配或未来可用性错误，先修复并新建协议版本，明确哪些旧证据受影响；若只是文本预算选择不同，不称作无代价bug修复，不混合新旧成绩。

## 四、五个实验块

### B1：补齐OT简单控制，并隔离反馈刷新（MUST）

**目的：** 回答ECmL组件问题及LCo1回放/比较问题，首先知道在线系统中的改动是否有独立价值。

full同一起始warm checkpoint的四种部署策略：

| 策略 | 更新参数U | 刷新梯度缓存F | 定义 |
|---|---|---|---|
| U0F0 | 否 | 否 | 已有iadapter_static，起始零反馈 |
| U1F0 | 是 | 否 | 正常成熟目标参数更新，hg/ge始终保持零；保留原网络和零输入下的bias路径 |
| U0F1 | 否 | 是 | 参数逐张量固定，只在成熟原点计算原数值/文本反馈并刷新缓存；无optimizer.step |
| U1F1 | 是 | 是 | 已有iadapter_online |

所有策略仍使用原full网络；不要用no_text_gradient/no_numeric_gradient替代F0，因为这些变体同时改了其他路径。U0F1的梯度计算不意味着更新权重，必须检查参数不变。缓存EMA=.9及原文本反馈定义不变。保存反馈tensor、参数更新时间、原点和原预测。回放每次使用原上下文。

**重要范围：** 四种策略的起点都已经在带反馈的训练流预热过，因此只隔离部署评分期间的反馈作用，不回答从训练到部署全程去除缓存的影响。已有整条训练路径消融作为另一张表保留。

另外新增每组：frozen_backbone、text_add_static、text_add_online。text_add使用现有加法结构、无文本梯度，保留其原数值反馈；static/online由同一份新预热权重分叉。新增text_add预热6次，用已有数值骨干和BERT缓存；不能复用不同目标通道的多变量text_add运行。

每组保留numeric_static、numeric_online及gpt4mts_static强参考。GPT在线扩展只在历史表保留，不作为成功门槛。

**数量：** 两域×三seed；full因子四格24，其中12复用、12新增；简单文本两个mode共12新增；裸骨干6新增。总计30新增评价单元、6次text_add训练流预热；上述10个系统/策略选项共60展示单元，含30个精确复用控制，不称60次新训练。

**指标：** 标准化MSE/MAE、逐seed差值和sample SD、更新数、参数位移、反馈范数、残差/基线预测幅度；保留每域最不利seed。

**C1开发门槛：** U1F1对U1F0平均MSE在两域各降低≥2%，平均MAE退化≤1%，每域至少2/3 seed改善MSE。只要一域未达到，就不将反馈普遍增益作为论文核心；仍报告四格及U0F1结果。此阈值是预先工程筛选，不是非劣效或显著性边界。

**C2初步门槛：** text_add_online相对numeric_online同样满足两域≥2%平均MSE、MAE退化≤1%、至少2/3 seed改善；同时报告text_add_static/frozen_backbone，不能只展示一个容易击败的在线控制。

**表图：** T1相同OT任务控制表；T2同起点U×F因子表。C1失败也能如实回答review，不追加delay网格。

### B2：文本可用性与内容读出（MUST，CPU为主）

**目的：** 区分“现有表示是否存在可读出的增量信号”和“full没有充分使用它”。这些是新的诊断，不能从当前同状态干预失败直接推断原始文本无信息。

固定骨干提取当前数值feature/历史描述符，不使用评价末尾adapter权重回放过去。用训练前缀拟合冻结线性Ridge残差读出，预测H=6各目标相对裸骨干预测的残差。允许使用训练标签拟合；选择段仅选预先固定的Ridge lambda，不携带其拟合状态到开发。

三个读出控制：

- P0：数值特征，文本metadata和content槽置零。
- P1：相同数值特征＋四个metadata（有效文本标记、可见字符长度、可见文本条数、最近文本年龄），content槽置零。
- P2：P1＋完整冻结BERT的16维训练前缀PCA表示。PCA和所有feature标准化仅拟合训练段；缺文本的content在投影后置零。
- P3：在同一冻结P2状态下，将content换成训练前缀informative donor，保持当前metadata。donor按dataset/seed/origin固定哈希选择，所有donor在当前原点前已可用，来源ID保存。P3是干预，不另拟合读出、不增加独立训练seed。

所有P0/P1/P2有相同feature槽位和输出接口；不使用任意大MLP检验信号。lambda只取{0.1,1,10}，以60–70% masked MSE选择，各控制拥有相同三个选择机会；没有hidden/dropout/grid搜索。每个horizon输出只用该输出有效目标拟合，评分统一原点/掩码。

**数量：** 六组×三个控制=18读出选择任务，最多54个lambda候选配置；每个配置分别求解6个带有效目标掩码的输出回归，不将这6个求解计作独立模型重复。再6个固定P2 donor干预序列。这不是18次神经模型训练或新数据确认。

**信号门槛：** P2相对P1满足两域平均MSE改善≥2%、MAE退化≤1%、每域至少2/3 seed改善；P3替换在每域平均MSE比P2更高。若只有P1比P0好，只能报告可用性/metadata有用，不称文本语义收益。

**解读与分流：**

- P2通过且B1简单文本也通过：已有原文表示/简单接入值得验证，跳过B3，不添加新LLM。
- P2通过但B1简单文本未通过：记录表示可读出、当前在线融合未获益。该轮不给full扩专家或直接上双路由；如需新接入机制，另立单一假设和预算。本计划不承诺从这一分支得到正面方法。
- P2未通过：可以触发B3的一次不同表示假设；B2失败不证明文本本身无信息，也不自动升级更大编码器。

**表图：** T3内容/可用性读出表；覆盖率和可见token分析放附录。预测关联不称因果机制。

### B3：一次TiMi式任务表示检验（CONDITIONAL）

**仅当：** B2未显示有效内容增量，M0来源/预算明确，且本地小模型资源就绪。当前只有BERT和GPT2权重，Qwen尚未下载；本轮计划没有安装或推理此模型。

借鉴TiMi的任务锚定与允许unknown，只判断目标OT在H=6范围内的趋势压力，五类INCREASE/DECREASE/STABLE/MIXED/UNKNOWN。不增加frequency/noise三头，不生成未来数值，不称输出为已识别的因果知识。

候选模型固定[Qwen2.5-0.5B-Instruct官方模型](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct)，执行时锁定revision、weights SHA与prompt SHA；冻结本地推理，greedy、max_new_tokens=8，只接受五个枚举，invalid映射UNKNOWN并保留原输出。先抽查两域各15条训练段文本，不查看未来标签；检查领域目标、格式、无依据强推断和未知类别处理。invalid超过5%或领域映射无法确定则停，不根据开发误差反复修改prompt/更换模型。

生成输入必须是当前BERT确实可见的原始文本字符串，加固定目标语义、采样频率和H；不能让LLM读被旧64-token截断的其余文本。未记录可信目标语义前不生成。无有效文本直接零表示，不进行LLM猜测。输出五维one-hot。

简单替代是预先写定的五类词汇规则：只读相同可见字符串；升降线索冲突为MIXED，无匹配为UNKNOWN。词表在训练文本检查后、开发标签不可见时冻结，版本记录；不依据开发成绩调整。

使用B2相同数值/metadata和Ridge读出。比较raw BERT训练PCA5、规则5维、LLM5维，统一槽位、mask和lambda机会，并对LLM内容做同状态历史donor替换。使用PCA5新参考而非将其与PCA16归为相同配置。

**数量：** 六组×三表示=18读出选择任务，最多54候选拟合；6个LLM donor干预。Energy/SocialGood前80%有1183+360=1543个非空独特选中文本；同可见字符串/prompt/horizon去重缓存后生成上限1543次，不按seed重复生成。记录总生成时间与token数。

**门槛：** LLM相对raw与规则均在两域平均MSE降低≥2%，MAE退化≤1%，每域至少2/3 seed改善；donor比正确表示的平均MSE更差。若规则更好或相当，优先规则并撤销LLM必要性主张。所有新输入仍须达到同样的内容/可用性区分条件，才进入B4。

TiMi参考：[论文v2](https://arxiv.org/abs/2602.21693v2)，尤其§3与附录C/E。这里只测试其一个思想，不是完整TiMi复现。语言模型的预训练可能覆盖这些历史年份；origin输入限制无法单独排除此影响，不能新增“无预训练泄漏”声明。

### B4：只有信号通过才验证简单部署（CONDITIONAL）

- 若B2与B1原text_add均通过：锁定原text_add结构，直接复用B1 static/online；只做对应的同状态内容干预和成本汇总，不新增神经评价单元。
- 若B3某一候选通过：只选一个表示（规则或LLM），与raw BERT-PCA5比较；候选选择规则固定为先满足门槛，再优先较低输入处理成本，而非最好seed。
- 两种表示均为5维，用同一5→96→64投影（ReLU、dropout=.1、LayerNorm与缺文本置零），接现有text_add结构；保留数值反馈、关闭文本梯度，无MoE/entropy。各方法共享相同形状初始参数与骨干；改变输入维度后不能复用原768维投影text_add作为该对照。
- 原5专家full、numeric_static/online、gpt4mts_static仍作为系统参考；它们与新raw/candidate的参数量不同，不称所有差异只来自表示。
- 每种表示每组训练流预热一遍，然后从同权重分别static/online评价，不让评价末权重回到过去；保存原梯度上下文与生成结果来源ID。

**数量上限：** 两表示×两mode×两域×三seed=24新增评价，12次预热，无新骨干；至多12条donor诊断序列，不计独立训练。

**准入B5：** candidate在线对同结构raw在线及numeric_online均满足两域≥2%平均MSE改善、MAE退化≤1%、每域≥2/3 seed改善；保留candidate静态结果。若online不优于candidate静态，不能将收益归因于在线适配，候选仅能作为静态文本方法线索，本轮不进入“在线方法确认”。

**成本：** 先比较全部参数、编码/生成、缓存预测、成熟更新、GPU allocated与CPU缓存，再对一个锁定候选和两个简单控制做两域×三轮隔离计时（18轮；每轮50预热/200测量）。生成成本另列，不把离线预处理隐藏为零。这里不重测原full全部成本。

**失败解释：** 有读出信号而部署失败，只说明这套简单在线接入未转化信号；撤销相应主张，不新增复杂路由追求翻盘。

### B5：锁定后追加域，并决定论文定位（CONDITIONAL）

当前本地存在Agriculture.csv和Health.csv，已确认文件与OT列，但尚未完成目标语义、健康数据区域身份、文本时间和schema验证。它们未进入本次修订190/静态75/在线75矩阵；原稿可能包含相关域，因此称“追加域验证”，不能称完全未接触的独立数据确认。

只有B4通过才进入，先锁定模型/表示/prompt/学习率，不再根据新域成绩选择策略。两域都完成数据身份审计后，固定OT、H=6、L=36、seeds2023–2027，60/20/20 chronological；训练文本/PCA/scaler仅训练前缀，选择骨干只用验证，评价期间遵循原成熟协议。报告与原70–80%开发表分开。若Health不符合已声明对象，暂停这一块并请求真实对应数据，不偷偷换域。

每域/seed五系统：frozen_backbone、numeric_online、raw_text_online、candidate_static、candidate_online。共50评价单元、10共享骨干；raw/candidate/numeric各训练流预热一次，共30预热，candidate两个mode共享warm状态。所有新骨干max30epoch/batch16/patience5/lr1e-3，minimal架构不改。若candidate就是原raw text，则两套重复系统合并为四系统，40单元；必须记录去重，不称50独立运行。

**论文决策：**

| 最终证据 | 正文主线与处置 |
|---|---|
| C1有稳定增量，C2无收益 | 聚焦限定场景的成熟反馈适配；text作为可选输入，不宣称文本语义贡献 |
| C2有内容收益，C1无增量 | 聚焦最简单有效文本接入；反馈/异构专家降级为未获支持的设计，不能仍将其列为核心贡献 |
| 只有开发有效、追加域失败 | 报告限定适用范围；选择确认资料或重构下一研究问题，不恢复广泛性能声明 |
| 两者均无有效证据 | 收束性能增强路线，保留协议/负结果贡献；当前证据不足以支撑原方法定位，需讨论新问题或论文重定位 |
| 内容与反馈都通过且追加域支持 | 再做result-to-claim判断并形成最小主线；仍不自动推导SOTA、因果语义或真实publication-time无泄漏 |
