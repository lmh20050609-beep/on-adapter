# 输入审计与可改进问题

M0还原Energy前1183和SocialGood前720原点，共1903行。原文本经过历史两条记录、字符裁剪和BERT64token后，与现有缓存选择完全一致。字段见evidence/m0/text_coverage.csv；完整逐原点来源保留experiments/replan_20260930/m0/。

SocialGood训练540原点中180有有效文本；选择和开发各90/90。360个缺文原点的所选原始字段本来为空，清洗后丢失有效信息的原点为0；因此覆盖差异发生在已提供原文层面，不能归因于本轮清洗。上游为何缺文仍未核验，不能用未来文本补训练空白。

Energy开发148行全部存在文本，但139/148的最新选中记录没有任何内容token进入BERT。SocialGood为16/90。这说明“选择了文本ID”与“模型实际看到其内容”不同。当前字符裁剪保留末尾1200字符，再由BERT取开头64token，顺序会使旧记录占据预算。此为明确的输入接入改善方向，尚未证明是误差退化原因。

下一种可行改进是相同64token预算内近期优先，与当前顺序进行同骨干、同初始化的简单加法融合对照；原评估保持不变，新的输入选择不是无代价恢复旧成绩。也可检验fact/preds分配，不同时搜索多个比例。本轮先完成固定表示探索，不把这些未执行候选写成已有成绩。

end_date仍仅为可用性代理；这些审计没有验证真实publication time或LLM预训练历史信息。
